# Sauda

Учёт товаров, касса и отчёты для розничных магазинов. Один сайт на много компаний: каждая видит только свои
магазины, товары и продажи.

## Что есть

- **Товары**: список с категориями, фильтрами и поиском, карточка товара и услуги, генерация штрихкодов
  (в том числе весовых), импорт и экспорт Excel, быстрые товары для кассы.
- **Склад**: остатки по магазинам, критические и минусовые остатки, история движения товара.
- **Документы** с черновиками: приёмка от поставщика с оплатами, оприходование, списание, перемещение между
  магазинами, инвентаризация (выборочная и полная). Остатки меняет только проведение.
- **Касса** в браузере: смены, сканер штрихкодов, весовые этикетки, скидки, оплата наличными и картой, сдача,
  возврат по чеку, внесение и изъятие, печать чека.
- **Отчёты**: статистика продаж (по товарам, чекам, категориям, поставщикам, покупателям), смены, кассиры, скидки,
  прибыли и убытки, ABC-анализ, отменённые товары.
- **Управление**: сотрудники с ролями (владелец, менеджер, кассир), кассы, торговые точки, покупатели и поставщики.

- **Накладные с фото**: приложение [«Накладные в Sauda»](https://github.com/backwardzz/umag-ocr) распознаёт фото накладной
  и кнопкой «В Sauda» открывает страницу `/#/invoice`, где из строк создаётся черновик приёмки. Товары ищутся
  по штрихкоду, недостающие создаются. Данные передаются в адресе после `#` и на сервер не уходят.

- **Поставщики и заказы.** Компания регистрируется как магазин или как поставщик (завод, дистрибьютор, торговый
  представитель). Поставщик ведёт каталог с ценами, упаковками и наличием и получает заказы магазинов: подтверждает
  (может уменьшить количество), отгружает. Магазин выбирает поставщика на витрине, видит свои остатки рядом с товарами
  каталога, одной кнопкой добавляет в корзину всё, что заканчивается, а отгруженный заказ принимает кнопкой «Принять
  товар» — создаётся черновик приёмки, недостающие товары заводятся сами.

Чек нефискальный: связи с ОФД нет.

## Запуск на своём компьютере

Нужны Node.js и запущенный Docker.

```bash
npm install
npm run db:start   # локальная база Supabase в Docker, первый запуск скачивает образы
npm run seed       # демо-магазин с товарами и продажами за две недели
npm run dev        # сайт на http://localhost:5181
```

Скопируйте `.env.example` в `.env.local`; адрес и ключ локальной базы печатает `npx supabase status`.
Для `npm run seed` в `.env.local` нужны ещё `DEMO_EMAIL`, `DEMO_PASSWORD` и `SUPABASE_SERVICE_ROLE_KEY` —
под этой почтой и паролем потом входите на сайт. `npm run seed -- --fresh` пересоздаёт демо-магазин с нуля.

Сидер создаёт два входа с одним паролем: `demo@sauda.test` — магазин, `rep@sauda.test` — торговый представитель
с тремя компаниями-поставщиками, каталогами и заказами в разных статусах.

Для разработки сидер заводит ещё вход **логин `dev`, пароль `admin1`** (почта `dev@sauda.test`) — владелец
демо-магазина и всех демо-поставщиков. В поле «Почта или логин» логин без «@» превращается в `<логин>@sauda.test`.
Сидер работает только с локальной базой, поэтому в облаке такого входа нет.

### Своя база товаров

```bash
npm run import -- "C:путьк выгрузке.xlsx" --org "Название компании"
```

Загружает Excel с товарами в отдельную компанию демо-аккаунта (без аргументов — `samples/catalog.xlsx` в компанию
«Шалкар»). Товар ищется по штрихкоду: повторный запуск с обновлённым файлом добавляет новые товары и обновляет
цены, названия, категории и поставщиков у существующих. Подходит выгрузка «Список товаров» из UMAG.
То же самое делает кнопка «Импорт / Экспорт → Импорт из Excel» на сайте. Папка `samples` в git не попадает.

## Проверки

```bash
npm test           # юнит-тесты и сквозной тест серверной логики на локальной базе
npm run build      # проверка типов и сборка в dist/
```

Сквозной тест и сидер работают только с локальной базой и отказываются запускаться на любой другой.

## Как устроено

- `supabase/migrations` — схема базы, права доступа (RLS) и серверные функции: продажа, возврат, смены,
  складские документы, импорт, отчёты. Новую миграцию к локальной базе применяет `npx supabase migration up`. Остатки и продажи меняются только через эти функции.
- `src/pages` — экраны кабинета и кассы, `src/ui` — общие компоненты, `src/lib` — работа с базой и расчёты.

## Выкладка в интернет

Сайт собирается и выкладывается на GitHub Pages сам при каждом пуше в `main` (`.github/workflows/pages.yml`).
Чтобы он работал у всех, ему нужна облачная база:

1. На [supabase.com](https://supabase.com) создать бесплатный проект, запомнить пароль базы.
2. На своём компьютере в папке проекта: `npx supabase login`, `npx supabase link` (выбрать проект)
   и `npx supabase db push` — миграции применятся к облачной базе.
3. В панели Supabase, Settings → API, взять Project URL и ключ `anon`. В репозитории на GitHub,
   Settings → Secrets and variables → Actions → Variables, создать переменные `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` с этими значениями.
4. В панели Supabase, Authentication → URL Configuration, указать Site URL `https://backwardzz.github.io/sauda/` —
   на него ведут ссылки из писем.
5. Перезапустить сборку: Actions → Deploy to GitHub Pages → Run workflow.
6. Вход `dev` / `admin1` в облаке: во временном `.env.local` указать облачные `VITE_SUPABASE_URL` и
   `SUPABASE_SERVICE_ROLE_KEY` (ключ `service_role` из Settings → API, никому не передавать) и выполнить
   `npm run dev-user`. Пароль `admin1` слабый: для настоящих магазинов заведите отдельные входы.

В облачном проекте оставьте включённым подтверждение почты: приглашения сотрудников срабатывают только для
подтверждённого адреса.
